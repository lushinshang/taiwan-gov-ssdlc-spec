資訊系統安全開發規範與委外廠商 SSDLC 執行程序書

依據《資通安全管理法》第10條、《資通系統防護基準》及工程會採購契約範本，明訂受託廠商全生命週期應遵循之各階段程序、控制措施與交付檢驗清單

規範適用：公務機關資訊系統委外建置、客製化開發與維運專案 版本發布：115 年最新防護基準版 文件責任：機關資通安全長 (CISO) 與資訊管理單位

零、 廠商遵循總則與法規效力聲明

本規範為本專案委外採購契約之不可分割附件。所有參與本機關資訊系統開發、建置、改版或維運之承辦廠商（以下簡稱「受託廠商」），於專案啟動日起必須嚴格遵照本程序書所定之 SSDLC 階段循序執行，未完成上一階段之安全審查與必要交付物，不得逕行進入下一階段。

⚖️ 法遵依據與法律拘束力（違約與稽核責任）：
  • 法源依據一：依 《資通安全管理法》第 10 條200 OK 及施行細則規定，公務機關委託法人辦理資通安全業務，應選任具備防護能力之廠商，並於契約明訂監督、稽核權及資安事件通報責任。
  • 法源依據二：依 《資通安全責任等級分級辦法》附表十「資通系統防護基準」200 OK （最新 115.01.07 修正），本案系統防護等級經評定為標準等級，廠商交付之系統控制項必須 100% 符合該基準要求。
  • 契約強制力：依 行政院公共工程委員會《資訊服務採購契約範本》(1131226 版)200 OK 第 8 條及附件《共通性資通安全基本要求》，各階段安全檢測未修補通過者，機關依法不得辦理驗收付款。

貳、 委外廠商 SSDLC 六階段循序執行程序

廠商專案經理（PM）與技術團隊必須嚴格按照以下順序推進專案，各階段之程序、安全控制措施與交付審查規定如下：

階段一：需求分析與資安規格確認程序 SSDLC PHASE 01
📋 執行程序與作業重點：
  • 程序 1.1 防護需求分級對齊：廠商系統分析師（SA）應依機關核定之資通系統防護等級（普、中、高），逐項核對本專案適用之安全功能需求。
  • 程序 1.2 人員資安保密簽署：專案啟動 14 日內，廠商指派之所有專案成員（含外包人員）必須全數簽署《專案人員資通安全保密協定（NDA）》，並送交機關存查備查。
  • 程序 1.3 產出規格專章：於《系統需求規格說明書（SRS）》中獨立設置「資通安全需求專章」，明確將身分鑑別、授權控管、稽核日誌與傳輸加密寫入功能清單。
📑 階段查核依據與交付表單：
1. 法規出處：《資通系統防護基準》附表九、附表十200 OK
2. 作業指引：參照 《安全軟體發展流程指引》 第 3 章需求階段規範。
3. 廠商應交付審查物：專案人員保密清冊、系統安全需求規格說明書、資安需求項目自評表。
階段二：安全架構設計與威脅建模程序 SSDLC PHASE 02
📋 執行程序與作業重點：
  • 程序 2.1 最小權限與職能分工 (PoLP & SoD)： 系統授權必須採用角色型存取控制 (RBAC) 架構。針對高防護等級系統或特定敏感情境，應規劃介接政府零信任架構或採用屬性型存取控制 (ABAC) 進行動態情境評估。
  • 程序 2.2 機敏資料傳輸與儲存保護： 所有網路連線必須強制採用 TLS 1.3（至少 TLS 1.2）加密通訊；使用者密碼強制採用具加鹽（Salt）的強固雜湊演算法（如 Argon2id 或 PBKDF2/bcrypt），嚴禁明文或弱雜湊（MD5/SHA1）。
  • 程序 2.3 身分鑑別架構： 提供特權管理功能之系統，強制規劃多因子身分鑑別（MFA），優先支援 FIDO 國際標準。
📑 階段查核依據與交付表單：
1. 規範出處：《附表十 資通系統防護基準》AC（存取控制）構面。
2. 作業指引：參照 《安全軟體設計參考指引》 第 4 章權限與架構設計。
3. 廠商應交付審查物：系統安全架構設計說明書（含資料流向圖 DFD 與網路邊界圖）、密碼學演算法使用清冊。
階段三：安全程式編寫與供應鏈管理程序 SSDLC PHASE 03
📋 執行程序與作業重點：
  • 程序 3.1 遵循 Web 安全開發規範： 程式碼撰寫必須嚴格遵循 NICS《Web 應用程式安全參考指引 v3.2》，徹底防範 OWASP Top 10 弱點：
    • 資料庫操作全面採用參數化查詢 (Prepared Statements)，嚴禁字串拼接 SQL。
    • 所有使用者輸入輸出必須進行 HTML / JavaScript 編碼，防範 XSS 攻擊。
    • 啟用 HTTP 安全標頭（HSTS、X-Content-Type-Options、CSP 等）。
    • 嚴禁於原始碼或組態檔中硬編碼（Hard-coded）帳號密碼、API 金鑰或憑證。
  • 程序 3.2 軟體供應鏈管理與產出 SBOM： 廠商必須於 CI/CD Pipeline 建立軟體成分分析（SCA），透過 `Syft` 或 `Trivy` 工具產出標準格式之軟體物料清單 (SBOM)（SPDX / CycloneDX 格式），比對並修補第三方開源套件之已知 CVE 漏洞。
  • 程序 3.3 嚴格禁止使用大陸廠牌產品： 依行政院政策規定，受託廠商交付之硬體、軟體、中介軟體或雲端服務，一律嚴格禁止採用大陸廠牌資通訊產品。
📑 階段查核依據與交付表單：
1. 規範出處：NICS 數位韌性教材 SBOM 實作指引200 OK、行政院限制使用危害產品原則。
2. 作業指引：參照 《附件1 Web應用程式安全查檢表.pdf》。
3. 廠商應交付審查物：安全程式撰寫自主查檢表、第三方套件清單與 SBOM 檔案、非大陸廠牌聲明書。
階段四：安全檢測與弱點修補驗證程序 SSDLC PHASE 04
📋 執行程序與作業重點：
  • 程序 4.1 原始碼安全檢測 (SAST，白箱)： 系統提送整合測試前，必須進行全系統原始碼安全掃描（白箱檢測），「高風險 (High / Critical)」與「中風險 (Medium)」漏洞必須全數完成修補，不得以誤判為由逕自忽視（若為誤判須檢附技術佐證證明）。
  • 程序 4.2 系統與 Web 弱點掃描 (DAST，黑箱)： 於擬真測試環境對作業系統、資料庫、網頁伺服器及應用系統執行弱點掃描，高、中風險漏洞於上線前必須修復完成並檢附複測報告。
  • 程序 4.3 滲透測試 (Penetration Testing)： 中防護及高防護等級系統，交付前必須由具公信力之合格資安人員執行模擬黑客攻擊之滲透測試，出具完整測試報告（含攻擊過程 PoC 截圖、CVSS 評分及改善建議）。
📑 階段查核依據與交付表單：
1. 契約依據：工程會《資訊服務採購契約範本》共通性資通安全基本要求一覽表。
2. 技術指引：參照 《安全軟體測試參考指引》。
3. 廠商應交付審查物：原始碼檢測報告與修補確認單、弱點掃描報告、滲透測試報告、弱點複測合格證明。
階段五：安全部署與系統上線驗收程序 SSDLC PHASE 05
📋 執行程序與作業重點：
  • 程序 5.1 正式營運環境安全加固： 正式伺服主機與資料庫必須完整導入政府組態基準 (GCB)；變更所有預設帳號密碼，關閉無關之作業系統服務、Debug 模式與通訊埠。
  • 程序 5.2 環境獨立隔離： 嚴格落實開發環境、測試環境與正式營運環境之實體或邏輯隔離，測試用之假資料或機敏測試帳號嚴禁帶入正式環境。
  • 程序 5.3 驗收點交與安全查核： 召開上線驗收審查會議，逐一勾稽契約資安要求，確認所有檢測報告皆已修補複測合格，簽核上線許可單。
📑 階段查核依據與交付表單：
1. 檢核標準：參照 《資通系統防護基準檢核表.docx》。
2. 廠商應交付審查物：GCB 套用檢測報告、系統部署配置清冊、系統上線前資安查驗單、源碼交付光碟/存儲媒體。
階段六：維運監控、弱點追蹤與變更管理程序 SSDLC PHASE 06
📋 執行程序與作業重點：
  • 程序 6.1 弱點通報比對與持續修補 (VANS)： 保固與維運期間，廠商必須持續追蹤軟體相依元件之最新 CVE 弱點，並配合機關「資通安全弱點通報系統 (VANS)」進行資產比對，接獲重大弱點通報時應於規定期限內完成修補更版。
  • 程序 6.2 系統變更申請與回滾機制 (Rollback)： 維運期間所有程式更版或設定異動，均需填寫《系統變更申請單》，詳載影響評估與回復演練計畫，經機關核可後方得在維護窗口執行。
  • 程序 6.3 備份驗證與災難復原： 依 3-2-1 原則執行資料與組態備份，每半年或一年定期配合機關辦理系統還原驗證演練。
📑 階段查核依據與交付表單：
1. 稽核依據：資安署 115 年資通安全實地稽核項目檢核表200 OK。
2. 廠商應交付審查物：季度弱點修補維護紀錄表、變更申請授權紀錄單、系統備份還原演練紀錄報告。

參、 廠商交付文件查驗對照與罰則說明

為確保廠商依約履約，本專案設置「SSDLC 交付關卡檢核機制」，未達驗收標準之罰則與處理原則如下：

SSDLC 階段 廠商應提送關鍵交付文件 機關審查標準 未達標準之處理與罰則
階段一 需求 保密協定、資安需求規格專章 專案人員全數簽署 NDA 限期 7 日內補正，否則不得進入實體開發
階段二 設計 安全架構設計書、RBAC/ABAC 設計 符合最小權限與 TLS 1.3 加密 架構審查未通過者退件重修
階段三 開發 SBOM 物料清冊、無大陸廠牌切結書 SPDX/CycloneDX 格式，無大陸廠牌 查獲大陸廠牌軟硬體者，依違約終止契約
階段四 測試 源碼檢測報告、弱掃與滲透報告 中高風險漏洞修補率達 100% 未修復前不得申報初驗或正驗，計入逾期罰款
