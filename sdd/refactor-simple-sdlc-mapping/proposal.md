## 為什麼做

目前的 `simple/index.html` 偏向廣義的資安觀念入門指引，尚未能與根目錄 `index.html`（官方《資訊系統安全開發與資安檢測作業規範》）的完整章節與法規要求精準扣合。
許多只熟悉傳統軟體開發生命週期（SDLC：需求 ➔ 設計 ➔ 開發 ➔ 測試 ➔ 驗收）的工程團隊，在面對這份充滿「法條拘束力、附表十防護基準、WBS/RACI、SBOM 供應鏈、NIST SP 800-88 磁碟抹除、SAST/DAST/滲透測試驗收前置門檻」的官方規範時，往往無法將法規術語轉化為實際開發與測試的具體工作。

本重構提案旨在將根目錄 `index.html` 中的**所有條文、管理流程與驗收標準**，100% 完整轉譯為「只懂 SDLC 的工程師看得懂的白話實戰指引」，讓工程師清楚知道自己在 SDLC 的哪一步該做什麼、該交什麼，並透過豐富圖解（`codex exec` 生成資訊圖）與指令範例無痛落地。

## 要改什麼

1. **結構 1:1 對齊官方規範，並建立「傳統 SDLC vs 政府 SSDLC」映射表**：
   - **規範零（法遵拘束力）** ➔ **SDLC 合約認知**：為什麼資安沒過會計不能撥款？法規義務如何變成專案驗收條件？
   - **規範壹（官方文件庫）** ➔ **SDLC 文件清單**：誰該填附表九（機關填）？我們廠商看哪一本（附表十與指引）？
   - **規範貳（專案計畫與管理）** ➔ **SDLC 計畫與 Sprint**：如何在 WBS/Jira 多加資安卡片、RACI 角色分配、事故發生「1 小時通報窗口」的白話流程。
   - **規範參（安全程式開發）** ➔ **SDLC Coding 階段**：OWASP Top 10:2025（SSRF、注入、XSS、認證越權）、密鑰治理、如何一行指令生出 SBOM（SPDX/CycloneDX）。
   - **規範肆（功能與系統測試）** ➔ **SDLC Testing 階段**：為什麼絕對不能 dump 正式機資料（脫敏四大招）、Unit Test 壞蛋負向測試、專案退租硬碟時的 NIST SP 800-88 磁碟安全抹除流程。
   - **規範伍（資安技術檢測）** ➔ **SDLC 驗收前大考**：白箱 Fortify/Checkmarx（中高風險歸零與誤判報告撰寫公式）、黑箱 AppScan/ZAP（防火牆白名單與 Swagger 準備）、滲透測試（防業務邏輯漏洞與自測複測技巧）。
   - **規範陸（交付物審查與驗收門檻）** ➔ **SDLC 結案交卷清單**：驗收當天究竟要交出哪些檔案（檢測原檔、修補對照表、SBOM、抹除切結書）。
2. **多圖示與生動視覺化**：
   - 整合利用已生成之 8 張 high-res 繁體中文 16:9 / 9:16 資訊圖（包含門禁、流水線、魔王拆解等）。
   - 針對「WBS/RACI/通報管理」與「NIST 磁碟生命週期抹除」新增專屬的直式 Mermaid 流程圖或新繪圖解。
3. **終端機指令與程式碼範例實用化**：
   - 提供產生 SBOM 的 CLI（如 `syft` / `cdxgen`）、抹除硬碟指令概念、SQLi/XSS 代碼對照。
4. **雙向跳轉機制**：
   - 每個章節頂部提供快速跳轉錨點，一鍵對應到根目錄 `../index.html` 的正式官方條文。
